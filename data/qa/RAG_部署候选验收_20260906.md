## 这轮实际解决了什么

1. **按完整问题检索，而不是增加主题白名单。** BM25 + 阿里 Qwen embedding + RRF + rerank 共享同一 runtime；计划区分必需条件、替代选项、观察重点、排除项，显式地区在接受及最终选品阶段均检查
2. **规划不可用不能悄悄绕过条件审核。** 支持规划的 provider 处理非随便逛逛请求时，没有有效初稿就返回 `RETRIEVAL_PLAN_UNAVAILABLE`；界面保留原题并提示服务重试，不声称馆藏没有资料
3. **真实图片与文字证据分开。** 图像预审核只授权可见特征；为实际最终选品预取图片，命中缓存不被占满的下载队列阻塞；历史/因果/材料不因看过图自动获准
4. **展签先写再核对。** writer 和独立 critic 复用同一张真实图片，共用 40 秒；critic 可看本件最多 6 条、每条 900 字符的原始来源，标明新增和截断，不冒充作者已看过这些内容
5. **拒绝或保留不确定，而不是补常识。** 原文“可能”“推测”“归属存疑”不能升级为确定事实；本地窄范围检查阻止本件已知材料词混入 image-only 句。该检查不是通用事实证明器
6. **公共文案分批核对。** 每批最多 6 字段、最多 2 并发。全局主张审核失败仍回退；仅展品选择说明/关系审核失败时，丢弃该批断言，替换为固定、无事实推断的观察提示，记录局部降级；不能用未通过的原文填回
7. **确定信息由程序渲染。** 章节导航从最终 item ID 与译名生成，不再由模型复述章节成员；机构名单只取实际展出的机构；原始候选池的覆盖声明不被直接复制成最终事实
8. **资源与部署。** 同一海报下载的瞬态网络/5xx 故障最多重试一次，不重发收费生图；Windows 构建包排除 Windows native 模块，在服务器安装精确 Linux sharp 版本并验证。SFTP 断线仅在已校验前缀 SHA 后断点续传
9. **整场目标不再等同每件条件。** RC6 的规划复核 v3 区分重要性与量化作用域；每件硬限制仍逐件 AND，必须回应的观察目标使用独立 `exhibitionSetRequirements`。默认至少一个直接见证明确标作产品门槛，不假称用户指定了数量。核心关系必须由同一件作品独立支持，不能拼接不同作品中的买者、卖者成为同场景互动；未知集合条件不删除合法背景对象，但最终缺少核心见证仍不得声称回答成功

集合条件复用原有审核调用、来源引用和图片权限，不新增一个串行模型阶段。检索池缺见证会进入既有受限恢复；最终编排若挤掉见证，只能用已审核候选修复，并保留已有文化覆盖、逐件条件和最后一件完整记录。持久化校验会再次核对最终成员、同题/同条件/同对象绑定。该机制能检查模型所声明的作用域与证据归属，不能证明模型对自然语言量词或画面的理解始终正确。

## 仍未通过的上线门

开放题在此前 137 题的结果里仍有明显证据准确率和跨文化覆盖缺口；本轮工程修复及少量完整生成回归没有重算并通过原定 Recall/nDCG/错误支持/地区覆盖总体阈值。旧指标完整保留在 `RAG_优化验收_20260906.md`，不能与本轮单例混算。

剩余错误不是只有馆藏数量不足：有检索关系误判、有限片段漏掉关键语境、模型看图误认、跨件比较过度推断，以及网络造成的降级。连续引文、正确 evidence ID、第二个模型说通过都不构成语义必然正确的证明。

12 道访客挑战题在第一次运行前冻结；后续均为同题回归，不再称未见 holdout。问题、期望和所有失败未被替换；授权 AI 审核不是独立人类金标准。本次不宣称任意用户问题已稳定成功。

浏览器自动化对临时 loopback 预览返回 `ERR_BLOCKED_BY_CLIENT`，未绕过该限制；临时预览服务已自动停止。因此本轮没有获得真实 3D 转向、展签拖拽/缩放、音频播放与 2D/3D 切换的浏览器证据，相关逻辑测试与 HTTP 检查不能代替这道门。

## 部署操作约定

先用 `scripts/package_release.py` 产生新目录包，再用 `scripts/stage_release_candidate.py` 校验并在新候选目录验证；脚本默认只读/校验，只有 `--execute` 才创建隔离候选。上传中断时，只有未解包且现有内容与本地前缀 SHA 一致才能 `--resume-upload`。

上线需保留现有凭据与用户数据，只切换已验证代码/资源；显式设置 `RAG_MODE=hybrid` 与正确的源/索引目录，保留既有 APP_ENV 及访问契约。`API_INTERNAL_URL` 必须指向服务器 API 回环地址；浏览器使用同源相对地址。生图和语音输出要继续映射到实际公开的媒体路由。不要直接上传未经清理的原 `.next/standalone` 或把本地 `.env` 覆盖到服务器。

详见 `deploy/RELEASE_READINESS.md`。工程可运行、内部试用、公开语义质量达标和已经切流是四个不同状态。
